    Floating Point Error Example

    8 minutes to read

    Last post, we talked about how to understand floating point error, but the only example we consider was the trivial case of a+b+ca + b + ca+b+c. In this post, we will consider the example of summing the reciprocal squares of the natural numbers up to nnn,

    sn=∑k=1n1k2,s_n = \sum_{k=1}^n \frac{1}{k^2_{}},sn​=k=1∑n​k2​1​,

    in two different manners, and see how the error bounds we arrive at are different. Most importantly, we will see how different the possible precision is.

    We start by writing out the sum as

    1+122+133+⋯+1(n−1)2+1n2.1 + \frac{1}{2^2} + \frac{1}{3^3} + \dots + \frac{1}{(n-1)^2} + \frac{1}{n^2}.1+221​+331​+⋯+(n−1)21​+n21​.

    The two methods of summation we will consider is summing up the numbers from left to right, and then from right to left.

    True Truncation Error

    Finding the limit of this summation is known as the Basel problem and was first solved by Euler when he was a young mathematician. The solution to the infinite sum is exactly π26\frac{\pi^2}{6}6π2​. However, we are not interested here in how to compute this. If you are interested in seeing some proofs, I recommend the stackexchange post here.

    We are also interested in the analytical error created by stopping out summation early at nnn instead of ∞\infty∞. This error is exactly

    ∑k=n+1∞1k2,\sum_{k=n + 1}^\infty \frac{1}{k^2_{}},k=n+1∑∞​k2​1​,

    which we can bound by the integral of the same monotonically decreasing function starting at nnn, which gives us

    ∑k=n+1∞1k2≤∫n∞1k2 dk=1n.\sum_{k=n + 1}^\infty \frac{1}{k^2_{}} \leq \int_n^\infty \frac{1}{k^2} \, dk = \frac{1}{n}.k=n+1∑∞​k2​1​≤∫n∞​k21​dk=n1​.

    Now, we know the analytical error of cutting off the sum early. This will be useful later in calculating how close we can come to the true limit of π26\frac{\pi^2}{6}6π2​ by increasing nnn. After a certain point, the increase in floating point error will counteract the change in analytical error. That will be our limit of accuracy, and increasing nnn will not let our calculation get any more accurate.

    Error Analysis

    Note: These sections will be very mathy, and if you are just interested in the difference in result and possible accuracy achieved, you can skip to the end where I will list the results.

    We will denote the kkkth term of the summation (in either direction) as aka_kak​. We will denote the nnnth partial sum as sns_nsn​. We will number the δ\deltaδ‘s which appear as either being attached to the term aka_kak​ (for the reciprocal inverse operation) or as being attached to the partial sum sns_nsn​. Then, our partial sums sn^\hat{s_n}sn​^​ have the recursive formula

    sn^=(s^n−1+an(1+δa1))(1+δsn)\hat{s_n} = (\hat{s}_{n-1} + a_n(1 + \delta_{a1}))(1 + \delta_{s_n})sn​^​=(s^n−1​+an​(1+δa1​))(1+δsn​​)

    with the base case

    s2^=(a1(1+δa1)+a2(1+δa2))(1+δs2).\hat{s_2} = (a_1(1 + \delta_{a1}) + a_2(1 + \delta_{a2}))(1 + \delta_{s2}).s2​^​=(a1​(1+δa1​)+a2​(1+δa2​))(1+δs2​).

    We are then going to solve for the absolute error, the term

    ∣sn^−sn∣| \hat{s_n} - s_n |∣sn​^​−sn​∣

    We subtract out the aia_iai​s in the true sum, and also ignore terms which multiply together δ\deltaδs. Thus, combining terms for each aia_iai​, we get

    a1(1+nδa1)+a2(1+nδa2)+a3(1+(n−1)δa3)+⋯+an(1+δan).a_1(1 + n\delta_{a1}) + a_2(1 + n\delta_{a2}) + a_3(1 + (n-1)\delta_{a3}) + \dots + a_n(1 + \delta_{an}).a1​(1+nδa1​)+a2​(1+nδa2​)+a3​(1+(n−1)δa3​)+⋯+an​(1+δan​).

    In order to make this easier to work with, we will add an additional a1δa1a_1\delta_{a1}a1​δa1​ to the error, which gives us the nice summation

    ∑k=1nak(n+2−k)δak.\sum_{k=1}^n a_k(n + 2 - k)\delta_{ak}.k=1∑n​ak​(n+2−k)δak​.

    Now, we can use this summation to bound the error in each of the two different cases.

    Left to Right Analysis

    In this case, we have terms

    ak=1k2a_k = \frac{1}{k^2}ak​=k21​

    which substitutes into the absolute error summation as

    ∑k=1n1k2(n+2−k)δak.\sum_{k=1}^n \frac{1}{k^2}(n + 2 - k) \delta_{ak}.k=1∑n​k21​(n+2−k)δak​.

    We already know that every δ\deltaδ is, by definition, of absolute value less than ϵ2\frac{\epsilon}{2}2ϵ​. Thus, we substitute that into the summation to get that

    ∣sn^−sn∣≤∑k=1nϵ2n+2−kk2≤ϵ(n+2)2∑k=1n1k2.| \hat{s_n} - s_n | \leq \sum_{k=1}^n \frac{\epsilon}{2} \frac{n + 2 - k}{k^2} \leq \frac{\epsilon(n + 2)}{2} \sum_{k=1}^n \frac{1}{k^2}.∣sn​^​−sn​∣≤k=1∑n​2ϵ​k2n+2−k​≤2ϵ(n+2)​k=1∑n​k21​.

    Above, we also removed the −k-k−k term, as we are trying to upper bound the error, and get a sufficient bound without it. We can then use the limit of the sequence sns_nsn​ to state that the sum term is upper bounded by π/6≤2\pi / 6 \leq 2π/6≤2. This gives us an error bound of

    ∣sn^−sn∣≤(n+2)ϵ.| \hat{s_n} - s_n | \leq (n + 2) \epsilon.∣sn​^​−sn​∣≤(n+2)ϵ.

    Right to Left Analysis

    When summing from right to left, the kkkth term is

    ak=1(n+1−k)2.a_k = \frac{1}{(n + 1 - k)^2}.ak​=(n+1−k)21​.

    which gives us an absolute error summation of

    ∑k=1nn+2−k(n+1−k)2δak\sum_{k=1}^n \frac{n + 2 - k}{(n + 1 - k)^2} \delta_{ak}k=1∑n​(n+1−k)2n+2−k​δak​

    which we split into two different sums to make the numerator and denominator cancel. We then see that the right side is the same sum as sns_nsn​, and as such can be bounded by 2ϵ2=ϵ2 \frac{\epsilon}{2} = \epsilon22ϵ​=ϵ.

    ∑k=1nδakn+1−k+∑k=1nδak(n+1−k)2≤∑k=3n+2δakk+ϵ.\sum_{k=1}^n \frac{\delta_{ak}}{n + 1 - k} + \sum_{k=1}^n \frac{\delta_{ak}}{(n + 1 - k)^2} \leq \sum_{k=3}^{n+2} \frac{\delta_{ak}}{k} + \epsilon.k=1∑n​n+1−kδak​​+k=1∑n​(n+1−k)2δak​​≤k=3∑n+2​kδak​​+ϵ.

    We then use the ϵ2\frac{\epsilon}{2}2ϵ​ bound on the sum of δ\deltaδ‘s. Then, we have the harmonic series starting at 3. The first term is always 1, so we can state that

    1+∑k=3n1k≤∑k=1n1k1 + \sum_{k=3}^n \frac{1}{k} \leq \sum_{k=1}^n \frac{1}{k}1+k=3∑n​k1​≤k=1∑n​k1​

    We can then use a known bound of the harmonic series up to kkk terms,

    ∑k=1n1k≤1+ln⁡n\sum_{k=1}^n \frac{1}{k} \leq 1 + \ln_{} nk=1∑n​k1​≤1+ln​n

    which lets us state that our sum starting at three is bounded by

    ∑k=3n1k≤ln⁡n.\sum_{k=3}^n \frac{1}{k} \leq \ln n.k=3∑n​k1​≤lnn.

    Putting it all together, we get an error bound of

    ∣sn^−sn∣≤ϵ2(2+ln⁡n).| \hat{s_n} - s_n| \leq \frac{\epsilon}{2}(2 + \ln n).∣sn​^​−sn​∣≤2ϵ​(2+lnn).

    Comparison and Meaning

    We now have an error bound for each summing method, listed below.

    MethodError Bound
    Left to Right≤(n+2)ϵ\leq (n + 2) \epsilon≤(n+2)ϵ
    Right to Left≤(2+ln⁡n)ϵ2\leq \frac{(2 + \ln n)\epsilon}{2}≤2(2+lnn)ϵ​

    Clearly, the order of growth of the error is hugely different. One is linear, and the other is logarithmic in the number of terms. It’s crazy to see this difference in error bounds on a simple summation, with such simple methods each way.

    Now that we see the difference in error bound, how does this affect how close this method can get to estimating the true limit of π2/6\pi^2 / 6π2/6? Clearly, neither can approximate it perfectly. However, how close does each get? And how many terms does it take?

    The way to solve this is to write an expression for our total error, in this case the total error is the sum of the floating point error and truncation error. Then, we will minimize this expression.

    Total Error= Truncation Error + Floating Point Error.\text{Total Error} = \text{ Truncation Error } + \text{ Floating Point Error}.Total Error= Truncation Error + Floating Point Error.

    In both cases, the truncation error is just 1n\frac{1}{n}n1​, as we proved above.

    Left to Right

    The total error is

    1n+(n+2)ϵ.\frac{1}{n} + (n + 2)\epsilon.n1​+(n+2)ϵ.

    We take the derivative with respect to nnn, and set it equal to 0.

    −1n2+ϵ=0  ⟹  n=1ϵ-\frac{1}{n^2} + \epsilon = 0 \implies n = \frac{1}{\sqrt{\epsilon}}−n21​+ϵ=0⟹n=ϵ​1​

    which will give us a maximum precision of

    ϵ+2ϵ+12ϵ≈225ϵ.\sqrt{\epsilon} + 2\epsilon + \frac{1}{\sqrt{2\epsilon}} \approx 2^{25}\epsilon.ϵ​+2ϵ+2ϵ​1​≈225ϵ.

    Right to Left

    The total error is

    1n+ϵ+ln⁡n2ϵ.\frac{1}{n} + \epsilon + \frac{\ln n}{2}\epsilon.n1​+ϵ+2lnn​ϵ.

    We take the derivative, and set it equal to 0.

    −1n2+ϵ2n=0  ⟹  n=2ϵ-\frac{1}{n^2} + \frac{\epsilon}{2n} = 0 \implies n = \frac{2}{\epsilon}−n21​+2nϵ​=0⟹n=ϵ2​

    which gives us a maximum precision of

    3ϵ2+ln⁡2ϵ2ϵ≈19ϵ\frac{3\epsilon}{2} + \frac{\ln \frac{2}{\epsilon}}{2}\epsilon \approx 19\epsilon23ϵ​+2lnϵ2​​ϵ≈19ϵ

    The Difference

    We see that in this case, the best accuracy achievable differs by more than 6 orders of magnitude, or 2212^{21}221. This is an absolutely massive difference. Of course, to achieve this level of accuracy, we have to run the program for similarly absurd numbers of iterations. For the left to right case, we need to sum about 67 million terms before our accuracy stops increasing (albeit slower than the right to left case). For the right to left, we get increasing accuracy all the way up to about 1 quadrillion terms. We will never want to evaluate this sum that far out, but it is a useful example to showcase the difference in error that we can get just by changing the order in which we do a simple sum.

    Overall, floating point error is generally very small, and usually negligible, relative to the size of your problem or the tolerance of a solution. However, it’s worth knowing how it works, what can help to make it less pronounced, and general floating point best practices. Of course, you can always just use 128-bit if you are concerned it will be an issue, and then your (floating point) errors will almost disappear.
